## Middleware model comparison

Express middleware is `(req, res, next) => void`. You call `next()` to pass control to the next layer, or call `res.json()` to short-circuit. Echo middleware follows the same pipeline idea but uses Go's error-return pattern and closures:

```go
// Echo middleware signature
func(next echo.HandlerFunc) echo.HandlerFunc
```

A middleware returns a new `HandlerFunc` that wraps `next`. Call `next(c)` to pass control forward, or return an error to abort.

export const tsMiddleware = `// Express middleware
function requestLogger(req, res, next) {
  console.log(req.method + " " + req.path);
  next();
}
app.use(requestLogger);`;

export const goMiddleware = `// Echo middleware
func RequestLogger(next echo.HandlerFunc) echo.HandlerFunc {
    return func(c *echo.Context) error {
        fmt.Printf("%s %s\\n", c.Request().Method, c.Request().URL.Path)
        return next(c)   // pass control forward
    }
}

e.Use(RequestLogger)`;

## Built-in middleware

Echo ships several production-ready middlewares in the `middleware` sub-package.

export const tsBuiltIn = `// Express with popular packages
import morgan from 'morgan';
import cors from 'cors';

app.use(morgan('combined'));
app.use(cors({ origin: '*' }));
// No built-in recover — need express-async-errors or similar`;

export const goBuiltIn = `// Echo built-ins — no extra packages needed
import "github.com/labstack/echo/v5/middleware"

e.Use(middleware.RequestLogger())  // request log via log/slog
e.Use(middleware.Recover())        // catches panics, returns 500
e.Use(middleware.CORS())           // default: allows all origins

// Restrict CORS to specific origins:
e.Use(middleware.CORSWithConfig(middleware.CORSConfig{
    AllowOrigins: []string{"https://example.com"},
    AllowMethods: []string{http.MethodGet, http.MethodPost},
}))`;

<TsGo ts={tsBuiltIn} go={goBuiltIn} />

Echo v5 logs with the standard library's `log/slog` — no custom logger interface. `RequestLogger()` uses `e.Logger` (a `*slog.Logger`); to control the fields, use `RequestLoggerWithConfig` and log the values yourself:

```go
e.Use(middleware.RequestLoggerWithConfig(middleware.RequestLoggerConfig{
    LogStatus: true,
    LogURI:    true,
    LogValuesFunc: func(c *echo.Context, v middleware.RequestLoggerValues) error {
        slog.Info("request", "uri", v.URI, "status", v.Status)
        return nil
    },
}))
```

## Middleware ordering

Just like Express, order matters. Middleware registered first runs first. RequestLogger and Recover should always be outermost so they see every request and catch every panic.

```go
e.Use(middleware.RequestLogger())  // 1st — log all requests
e.Use(middleware.Recover())        // 2nd — catch panics from any later handler
e.Use(authMiddleware)              // 3rd — auth checks after logging is set up
```

## Route-level and group-level middleware

In Express you pass middleware directly to a route. Echo supports the same with `.Use` on a group.

export const tsRouteMiddleware = `// Express — per-route middleware
app.get('/admin', authMiddleware, adminHandler);

// Express — router-level
const adminRouter = express.Router();
adminRouter.use(authMiddleware);
adminRouter.get('/', adminHandler);
app.use('/admin', adminRouter);`;

export const goRouteMiddleware = `// Echo — per-route middleware
e.GET("/admin", adminHandler, authMiddleware)

// Echo — group-level middleware
admin := e.Group("/admin")
admin.Use(authMiddleware)
admin.GET("", adminHandler)
admin.GET("/users", adminUsersHandler)`;

## Writing a custom auth middleware

export const tsAuthMiddleware = `// Express JWT-like auth middleware
function requireAuth(req, res, next) {
  const token = req.headers.authorization?.split(' ')[1];
  if (!token) return res.status(401).json({ message: 'unauthorized' });
  try {
    req.user = verifyToken(token);
    next();
  } catch {
    res.status(401).json({ message: 'invalid token' });
  }
}`;

export const goAuthMiddleware = `// Echo custom auth middleware
func RequireAuth(next echo.HandlerFunc) echo.HandlerFunc {
    return func(c *echo.Context) error {
        header := c.Request().Header.Get("Authorization")
        if header == "" {
            return echo.NewHTTPError(http.StatusUnauthorized, "missing token")
        }
        parts := strings.SplitN(header, " ", 2)
        if len(parts) != 2 || parts[0] != "Bearer" {
            return echo.NewHTTPError(http.StatusUnauthorized, "bad token format")
        }
        claims, err := verifyToken(parts[1])
        if err != nil {
            return echo.NewHTTPError(http.StatusUnauthorized, "invalid token")
        }
        // Store claims in context for downstream handlers
        c.Set("user", claims)
        return next(c)
    }
}`;

<GoOnly title="Storing values in context">

`c.Set(key, value)` stores an arbitrary value in the request-scoped context. Retrieve it with `c.Get(key)` and a type assertion, or with the generic `echo.ContextGet`, which returns an error instead of panicking on the wrong type. This is the equivalent of `req.user = claims` in Express:

```go
claims := c.Get("user").(*MyClaims)            // panics if the type is wrong

claims, err := echo.ContextGet[*MyClaims](c, "user")   // error if missing or wrong type
```

Use typed keys (a local `type contextKey string`) to avoid collisions in larger codebases.

</GoOnly>
