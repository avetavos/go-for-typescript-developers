## Layout comparison

A TypeScript/Node project carries `package.json`, a build tool, a `dist/` output folder, and `node_modules`. A Go project is simpler: `go.mod` declares the module and its dependencies; there is no separate build-output folder — `go build` produces a single binary.

export const tsLayout = `// Express / NestJS project tree
my-api/
  package.json
  tsconfig.json
  src/
    main.ts
    app.module.ts          // NestJS root module
    books/
      books.controller.ts
      books.service.ts
      books.dto.ts
    middleware/
      logger.middleware.ts
  node_modules/`;

export const goLayout = `// Echo project tree
books-api/
  go.mod
  go.sum
  main.go                  // entry point; wire everything here
  internal/
    handler/
      books.go             // HTTP handlers (parse, validate, call service)
    service/
      books.go             // business logic
    store/
      books.go             // database queries
  model/
    book.go                // shared structs / domain types`;

## go.mod — the package.json of Go

`go.mod` declares the module path (used as the import prefix) and the minimum Go version. `go get` adds dependencies; `go mod tidy` removes unused ones.

export const tsPackageJson = `// package.json
{
  "name": "books-api",
  "version": "1.0.0",
  "dependencies": {
    "express": "^4.18.2"
  },
  "devDependencies": {
    "typescript": "^5.0.0"
  }
}`;

export const goModFile = `// go.mod
module github.com/you/books-api

go 1.27

require (
    github.com/labstack/echo/v5 v5.3.1
)`;

## main.go — wiring the application

In NestJS, `main.ts` calls `NestFactory.create`. In Echo, `main.go` calls `echo.New()`, registers middleware and routes, then calls `e.Start`. All wiring is explicit Go code — no decorators, no DI container.

export const tsMainTs = `// NestJS main.ts
import { NestFactory } from '@nestjs/core';
import { AppModule } from './app.module';

async function bootstrap() {
  const app = await NestFactory.create(AppModule);
  app.setGlobalPrefix('api');
  await app.listen(3000);
}
bootstrap();`;

export const goMainGo = `// main.go
package main

import (
    "log/slog"
    "os"

    "github.com/labstack/echo/v5"
    "github.com/labstack/echo/v5/middleware"

    "github.com/you/books-api/internal/handler"
    "github.com/you/books-api/internal/store"
)

func main() {
    e := echo.New()

    // Middleware
    e.Use(middleware.RequestLogger())
    e.Use(middleware.Recover())

    // Dependency wiring (manual, no container)
    bookStore := store.NewBookStore()
    bookHandler := handler.NewBookHandler(bookStore)

    // Routes
    api := e.Group("/api")
    api.GET("/books", bookHandler.List)
    api.POST("/books", bookHandler.Create)
    api.GET("/books/:id", bookHandler.Get)
    api.PUT("/books/:id", bookHandler.Update)
    api.DELETE("/books/:id", bookHandler.Delete)

    if err := e.Start(":1323"); err != nil {
        slog.Error("server stopped", "err", err)
        os.Exit(1)
    }
}`;

<TsGo ts={tsMainTs} go={goMainGo} />

`e.Start` blocks until the server stops and returns the reason as an error — there is no `Fatal` on a `*slog.Logger`, so you log and exit yourself. When you need graceful shutdown or TLS, use `echo.StartConfig` instead:

```go
sc := echo.StartConfig{Address: ":1323", GracefulTimeout: 10 * time.Second}
if err := sc.Start(ctx, e); err != nil {   // returns when ctx is cancelled
    slog.Error("server stopped", "err", err)
}
```

<GoOnly title="Why internal/?">

The `internal/` directory is a Go language feature: packages inside it can only be imported by code in the same module. It is the idiomatic way to keep handlers, services, and stores private — equivalent to marking a NestJS module as non-exported. Any attempt to import `github.com/you/books-api/internal/handler` from outside the `books-api` module will fail at compile time.

</GoOnly>
